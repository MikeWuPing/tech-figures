# 技术配图

给技术文章做配图的一套完整管线：**HTML/CSS 编写 → Chromium 截图**。
不写绘图代码算坐标，排版交给浏览器。

一句话原则：**技术元素由代码精确绘制，底图只负责氛围，文字永远由代码叠加。**

## 开工前先判断

- 图里要表达**准确的技术内容**（框图、时序、对照表、位域）→ 走本 skill 的 HTML/CSS 管线
- 只想要**氛围、质感、封面** → 先备一张底图，见下面的「底图从哪来」
- 两者都要 → 先备底图，再用 HTML/CSS 在上面叠加内容

**不要用 AI 画技术内容。** 实测它画不出准确的框图连线，还会在画面里生成看起来像字的乱码。

## 底图从哪来

三条路，**按需选，没有哪条是必须的**：

| 来源 | 什么时候用 | 代价 |
|---|---|---|
| **本地 ComfyUI 生成** | 想要可控的构图和色调，或找不到合适的现成照片 | 要装 ComfyUI 和模型；出图有随机性，得挑 |
| **公有领域照片** | 手头有现成的好素材时。真实照片质感往往更好 | 受限于能找到什么；要确认授权 |
| **纯色 / 渐变** | 只求干净，不要质感 | 最省事，观感平 |

工具链**不依赖任何一种底图**：`make_bg.py` 能处理任意图，`.bg` 也可以留空走兜底色。
机器上没装 ComfyUI 就换另外两条路，管线的其余部分照常工作。

ComfyUI 怎么找、怎么调用、有什么坑，见 `references/ai-images.md`。

## 工具箱

`assets/` 下的文件按需复制进项目（**skill 是自包含的，直接拷**）：

| 文件 | 作用 |
|---|---|
| `setup.py` | **开工第一个跑它**。建目录、拷工具链、探环境（Chrome / playwright / 字体 / ComfyUI） |
| `figkit.css` | 配图设计系统。配色变量、玻璃面板、节点、对照矩阵、分层剖面、标尺、说明条 |
| `figkit.js` | 连线绘制。`wire(起点, 终点, 选项)` 自动布线 |
| `render.py` | Playwright 驱动本机 Chrome 出图，不下载浏览器、不联网 |
| `cover.css` | 封面图的版式（16:9，左侧压暗放标题） |
| `make_bg.py` | 把任意图处理成底纹，**自动校准亮度** |
| `comfy_gen.py` | 本地 ComfyUI 的调用器 |

```bash
python <skill>/assets/setup.py              # 在当前目录铺开
python <skill>/assets/setup.py --check      # 只探环境，不落文件
```

`setup.py` **不覆盖已存在的文件**，重复跑是安全的。

`examples/` 下四个可直接抄的样板：`example-panels`（两栏+连线）、`example-matrix`（对照表）、
`example-timeline`（时间轴+标尺）、`example-cover`（封面）。

## 目录约定

```
<项目根>/
  figs.conf              可选，写「模板前缀 = 输出目录」
  fig/                   名字随意
    render.py
    t/*.html             每张图一个模板
    _asset/              底图与素材
```

开工第一步，把 `assets/` 里的东西拷进项目的 `fig/`，建好 `fig/t/` 和 `fig/_asset/`，
然后写 `figs.conf` 声明输出目录：

```
gen  = figs
ddr  = figs/ddr
```

**输出路径必须和文章里的 `![]()` 引用一致**——先看文章怎么引用，再定配置。
写反了图会落到没人读的地方，而且不报错。

## 工作流

1. **先立设计系统，再建样板。** 不要一上来批量做。挑一张最有代表性的图，把配色、
   组件、字号调到位，**渲染出来亲眼看**，确认后再照着它铺开。
2. **每张图渲染后必须 Read 看一眼。** 溢出、重叠、文字被裁、连线没画出来——这些
   代码不报错，只有看图才发现。
3. **批量时可以并行分派子 agent**，每组带上设计系统文件和已完成的样板当参照。
   但**必须逐张验收**：子 agent 会漏内容、会重新引入已经修好的错误。
4. **改完底图或配色，重渲全部**（`render.py --all`），并确认文章引用的图仍然都在。

## 铁律

这些都是踩过的坑，按严重程度排：

1. **图内不出现「图 N」编号。** 作者要能自由调整图片顺序，编号写死在图里会全部错位。
   正文里的 `![图 N：…]` 是 Markdown 文本，可以随便改，图里的不行。
2. **从旧图迁移时，内容一字不漏。** 标题、副标题、每个方框里的字、说明句、底部图注，
   全都要搬过去。这是最容易犯也最严重的错误——新图更好看了，但少了内容，
   价值反而下降。**搬完逐条核对一遍。**
3. **图里的数值必须和正文对得上。** 图往往是从正文派生出来的，正文改了图没跟上就会
   自相矛盾。迁移时顺手核一遍事实。
4. **厂商内部块名换成功能性描述。** 内部代号（项目代号、模块缩写）对读者无意义。
   写它做什么，不写它叫什么。
5. **AI 生成的字一个都不能用。** 模型会在不该有字的地方生成伪文字，缩略图上根本看不出来，
   必须放大看。**图内所有文字由代码叠加。**
6. **不声称 AI 生成图是实物。** 发表时标「示意图 / 概念图」，不标「摄影」。

## 用色语义（务必遵守，别混用）

| 颜色 | 含义 | 类名 |
|---|---|---|
| **蓝** | 本代 / 主角 / 新方案 | `.node.acc`、`.col-hi`、`.c.hi` |
| **暖（琥珀）** | 对照方 / 上一代 / 竞品 | `.node.warm`、`.c.warm` |
| **红** | 代价 / 警示（漏电、冲突这类） | `.c.bad`、`var(--red)` |

红和暖是**两套不同的语义**。暖说的是「这是别人家的」，红说的是「这里要付代价」。
不要因为都是暖色调就并成一个。

## 排版

- 画布宽度默认 1200 CSS px，高度按内容定（正文类 560～760，内容密的可以到 820）
- 输出按 2 倍像素密度（1200×640 → 2400×1280），平台缩放后文字依然锐利
- 字号：主标题 27px、副标题 14.5px、面板标题 16.5px、正文 13.5px、图注 12px
- **留安全边距。** flex 布局本来就不会溢出，但绝对定位的元素会，宁可少放一点

模板在 `<head>` 里声明画布尺寸：

```html
<meta name="fig-size" content="1200x640">
```

## 常见技术坑

- **`.wires` 的 z-index 必须高于内容层**（`figkit.css` 里已设成 9）。被内容层压住的话
  连线会整个不显示，而且不报错。
- **底图不要再压亮度。** 处理过的底图本身已经很暗（均值 30 左右），CSS 里再来一次
  `brightness(.36)` 会黑成一片。要压就用 `make_bg.py` 的自动校准。
- **`wire(..., straight: true)` 用于扇入到宽底板**（多根线各走各的，不收到中心点）。
  但**同一源点分出多根线时不能用 straight**，会塌成一条。
- **绝对路径别写进模板。** 模板里用相对路径（`../../_asset/bg.png`），
  CSS 里的相对路径是相对 CSS 文件解析的，跟模板不是一回事。
